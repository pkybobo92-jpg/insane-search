# HybeFiller 1.3.1 재점검 결과

검증일: 2026-11-03. Windows / Python 3.14 / PyInstaller 6.19 환경에서 검사했습니다.

## 통과

- 합성 자료 단위·회귀 테스트 **51개 통과, 실패 0개**. 이전 26개에 데이터 오기재 경로와 저장 실패·경합 검증을 추가했습니다.
- 최종 Windows 실행파일로 분리 보관된 PDF **88개, 1,106쪽**을 처리했습니다. **2,552개 업무 셀**이 직접 원문 대조한 기준값과 일치했습니다. 비교용 엑셀에서 값을 채운 횟수는 0입니다.
- 필수값 확정 57건, 일부 확인 필요 31건, 처리 실패 0건. 불확실한 핵심 항목 **42개는 실제 빈 셀**로 유지했고 원문 페이지·보류 사유도 확인했습니다.
- PDF·원본 압축파일·양식·참고 엑셀·검토확정 파일 등 **93개 입력 파일의 SHA256 보존**을 확인했습니다.
- 새 캐시에서 OCR 모델을 실행했습니다. 검토확정 파일이 없으면 금액·수량·SKU를 기재하지 않았습니다. PDF 바이트를 변경하면 이전 검토확정 값을 적용하지 않았습니다.
- 합성 **1,000행·29,000개 업무 셀**을 생성하고 저장 후 대조했습니다. 이 PC에서 약 20.28초가 걸렸습니다. 실제 PDF OCR 1,000건 처리 시간은 아닙니다.
- 결과 표·숫자·검토내역을 이미지로 렌더링하여 한글, 소수 표시, 앞자리 0과 빈칸을 확인했습니다.
- 소스와 배포물에는 고객 PDF, 실적 엑셀, 실제 검토확정 값, 분석 캐시, 감사 로그를 포함하지 않습니다.

## 차단한 주요 경로

1. 캐시에 남은 네이티브 텍스트·좌표로 값 확정: 실제 PDF 스냅샷에서 매번 다시 추출합니다.
2. 해시 계산과 분석 사이 원본 변경: 동일 스냅샷 바이트에서 해시와 추출을 수행하고 저장 직전에도 입력 해시를 검사합니다.
3. 검토확정 파일에 의한 House BL 변경, 다른 HBL 인보이스, 중복 JSON 키, 누락된 `value`, 일부 필드만 적용된 상태: 검증 전체를 마친 뒤 적용합니다.
4. 다른 PDF의 근거 재사용, 잘못된 숫자·정밀도·날짜: 출력 직전에 다시 검사해 부적합한 값은 비웁니다.
5. 기존 실적이 들어 있는 양식의 무검토 복사: 빈 양식만 허용합니다.
6. 소수 표시 반올림, 저장 중 값 변경, 출력 파일명 경합: 표시 자릿수를 보존하고 재개봉 대조 후 기존 파일을 덮어쓰지 않는 방식으로 저장합니다.
7. 중복 허용 옵션으로 수정본 충돌 우회, 같은 HBL의 실패한 수정본 무시, 한 PDF의 여러 HAWB에서 파일명으로 선택: 해당 문서들을 보류합니다.
8. 인보이스에 언급된 HBL을 HAWB 자체 번호로 오인, 다른 문서의 Incoterms 연결, 같은 페이지의 상충하는 Invoice No. 중 첫 값 선택: 명시된 원문 연결과 모든 후보를 확인합니다.
9. 회사명 좌표 경계에서 단어가 잘린 값 출력: 확정하지 않습니다. 옆 날짜 열의 잘림이 명확한 공항명을 지우지 않는 것도 검증했습니다.
10. 저장 검증 실패 시 Windows 파일 핸들이 임시 파일 정리를 방해: 읽기 반복자와 파일을 닫고 임시 파일을 정리합니다.

## 실패 / 미확인

- 최종 실행에서 실패한 검사는 없습니다. 오류가 나야 하는 부정 테스트는 의도한 보류·중단을 확인했습니다.
- GUI 직접 클릭은 수행하지 않았습니다. 컴퓨터 유즈는 사용하지 않았고, GUI EXE 버전 모드와 같은 처리 엔진을 쓰는 CLI를 검사했습니다.
- 제공되지 않은 서식, 처음 보는 문서, 실제 매크로 실행·복잡한 Excel 개체는 검증하지 않았습니다. 현재 House BL 인식 범위는 README에 기재되어 있습니다.
- 검토확정 JSON은 사람이 원문을 대조했다는 입력입니다. 파일 형식·연결·해시 검증이 그 판단 자체의 사실성을 증명하지는 않습니다. 원문이 모순되거나 명확하지 않으면 `null`로 보류해야 합니다.
- 유한한 테스트로 무결함이나 모든 미래 입력의 무오류를 보장할 수 없습니다. 미확정 항목을 임의로 채우지 않는 방식으로 운영해야 합니다.
