# HybeFiller 1.3.1

Windows PDF → Excel 업무 도구. 원문에서 확정한 값만 기재하고, 판단이 안 되는 값은 빈칸으로 남깁니다.

## 입력 원칙

- 참고 Excel은 차이 비교에만 사용하며 출력값을 채우거나 덮어쓰지 않습니다.
- HAWB/Manifest의 명시된 텍스트 필드와 검토확정 JSON을 사용합니다. 금액·수량·SKU의 OCR 결과, 단가 역산, 행 개수 추정값은 자동 확정하지 않습니다.
- 동일 PDF 안의 HAWB 사본들을 모두 대조합니다. 청구중량이 다르면 해당 중량을 비웁니다. Gross Weight나 CT 개수로 대체하지 않습니다.
- 검토확정 JSON은 직접 대조한 PDF의 SHA256 및 페이지를 포함해야 합니다. 파일 내용이 바뀌면 과거 확정값을 적용하지 않습니다. `null`은 명시적 보류입니다.
- 같은 House BL의 내용이 다른 PDF를 동시에 넣으면 기본적으로 양쪽 모두 보류합니다. 동일 바이트 원본의 재선택은 중복 제외합니다.
- 원본과 기존 결과를 덮어쓰지 않습니다. 결과에는 `검토내역`, `원문근거`, `.review.csv`, `.audit.jsonl`이 함께 생깁니다.
- 양식의 업무 열에는 기존 값이나 수식이 없어야 합니다. 기존 실적 파일은 비교용으로 지정합니다.
- 원문 텍스트와 좌표는 캐시에 관계없이 PDF에서 다시 읽습니다. SHA256은 실제 분석한 동일 바이트에서 계산합니다. 분석·저장 중 입력이 바뀌면 해당 문서를 보류하거나 저장을 중단합니다.
- 검토확정 파일은 House BL을 바꿀 수 없습니다. 중복 JSON 키, 누락된 `value`, 잘못된 페이지·날짜·숫자·다른 HBL의 인보이스는 오류로 남깁니다. `null`로 보류하려면 명시적으로 기록해야 합니다.
- Excel에서 정확하게 보존할 수 없는 숫자는 넣지 않습니다. 소수부는 표시 형식에서도 생략하지 않으며, 저장 후 모든 업무 셀을 다시 대조한 파일만 최종 이름으로 저장합니다.
- `--allow-duplicates`는 동일 원본의 중복 행만 허용합니다. 내용이 다른 수정본, 같은 HBL의 실패한 문서, 한 PDF에 섞인 여러 HAWB를 자동 선택하지 않습니다.

## 실행

포터블 폴더 전체를 압축 해제하고 `HybeFiller_v1.3.1.exe`를 실행합니다. `_internal` 폴더를 함께 유지하세요. 제공된 동일 자료를 재생성할 때는 별도로 전달된 `reviewed_values_v1.3.1.json`을 선택합니다. 이 파일에는 업무 데이터가 들어 있으므로 프로그램 공개 배포물과 분리합니다.

새 스캔 PDF는 원문을 대조한 검토확정 파일이 없으면 금액·수량·SKU가 빈칸입니다. 임의의 JSON이나 참고 Excel만으로 확정하지 마세요. 완전히 이미지로 된 HAWB 등 대상 운송장 텍스트를 확정할 수 없는 형식은 오류 기록으로 남습니다. 현재 인식 대상 House 형식은 `PLIHQ2` + 영문자 + 5자리 숫자입니다. 인식하지 못한 긴 번호를 잘라 쓰지 않습니다.

CLI 예시:

```powershell
.\HybeFillerCLI.exe --pdf .\input\sample.pdf --template .\Template.xlsx --output .\result.xlsx --reviewed .\reviewed.json
```

`--reference comparison.xlsx`은 비교 전용입니다. `--dry-run`은 진단 로그만 만듭니다. `--help`에 전체 옵션이 있습니다.

## 개발과 빌드

```powershell
py -3.14 -m pip install -r requirements.txt
py -3.14 -m unittest discover -s tests -v
py -3.14 src/main.py --help
.\build.ps1
```

`src/app`은 읽을 수 있는 Python 소스입니다. 이전 배포본의 비공개 파서 바이트코드는 사용하지 않습니다. 빌드 산출물은 `dist/HybeFiller_v1.3.1_portable`입니다. 테스트는 합성 자료를 사용하며 고객 PDF/Excel이나 실제 확정값을 저장소에 포함하지 않습니다. 런타임 OCR 모델은 패키지에 포함되며 별도 API 키가 필요하지 않습니다.

`필수값 원문 확정` 상태는 HBL·인보이스번호·금액·수량·SKU가 확정되었다는 뜻입니다. 모든 29개 업무 항목이 채워졌다는 뜻은 아닙니다. 미확정 업무 날짜, 요청자, 픽업지 등은 계속 빈칸이며 이유를 `원문근거`에서 확인할 수 있습니다. Invoice Value는 원문에 명시된 인보이스 총액을 기록하며 FOB나 운임보험과 구분한 근거를 함께 보존합니다. 원문에 통관용 신고가액이라고 적힌 경우 그 사실도 검토 근거에 기록합니다.
